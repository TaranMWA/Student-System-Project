# Student-System-Project
Project using Python to create a system to manage student data. This code can be altered to manage other data, different versions have been made and each version is an improvement of the last. All code can be run directly from IDLE.

For the final version I created 3 demo accounts which can be used to log in as an admin, teacher and student respectively. The details are at the bottom of the page when the system opens. There are also pre-populated dummy accounts and information so that anyone can see how the system works and play around with all the features without having to input a large amount of data first. For a working version to be rolled out, the data inputted can simply be cleared and the blank system is ready to use.

Throughout this project there has been improvements made at each step of the process, resulting in 4 different working versions of the project. This has come from feedback from and collaboration with members of my college class. The biggest change was the designs of each version of the system. The first version was solely focused on working Python code, design wasn’t a key aim therefore all that needed to be met on the design aspect was that it was easy for a user to understand the system. As this project progressed I used more capabilities of Python such as the Tkinter library to make the system more of a working professional application and focused towards end user interaction – creating things like buttons, using different colour schemes, creating pop ups and having different dashboards. 

Version 1:
Version 1 is a basic system run by Python directly from the terminal. Upon opening the file the system will open and 16 options will be visible, to select an option the user must key in the corresponding number and press enter – for example to add a new student the user must press “1” then “enter” to be able to access the screen to add a new student. Once an option is selected the user must type in all required information displayed, pressing “enter” to input each parameter. If all inputs are entered correctly then the option will be executed, if not an error message will be shown with the reason for failure, the user will then have to start the option from the beginning. For example, student ID must be unique, if it is not the system will tell the user and they will be sent back to the main menu. They system works with an SQLite file that is saved in the same folder as the Py file, each transaction is updated in the database after the option has been completed. There are no clicks required in this programme, once finished user can select option “16” to exit the programme. Upon opening again, the data from the previous session will still exist in the SQLite database.

Version 2:
Version 2 works the same as version 1, except now there is a log in system upon start up. The programme will show 3 options, “1” is to log in, “2” is to register a new account and “3” is to close the programme. For the first time using this version, there will be no accounts saved in the database so the user will need to select “2” and press “enter”, they will need to input required fields and choose if they are a student, teacher or admin. Then the user will need to select “1” and log in with the details they have just created. This information will be saved to the SQLite database so next time the programme is used this same user can select “1” and log in again. Depending on what account is created determines what options will be available – admin can see all available options, teacher cannot see option 2, 5, 8, 9, and 11, and student can only have access to options 3, 4, 6, 7, 12, 14, 15, and 16.

Version 3:
Version 3 now includes a user interface created with Tkinter, the backend code is the same and still used Python and SQLite to link to a database file. The user interface is basic, but shows the same options available on a sidebar. Upon start up there one log in screen with two buttons for the user to decide if they want to log in with an existing account or register a new one. This version uses point and click to select options as well as typing inputs, the sidebar with the options are always visible, each option selected will appear in a bigger main screen.

Version 4:
Version 4 works the same as version 3, however the designs and colours are much more comprehensive and works as a working app. As all versions before, admins, teachers and students have different options available to them based on what account the user logs in as, this time each type of user account have different colours shown (green for admin, pink for teacher and blue for student). There is still a side bar with buttons to press for options but there are also buttons at the top and right side of the page, making the system more interactive, visually pleasing and clearer to use and understand. Some options take the user to a different screen and some options open up another smaller window, again adding to the user experience. This version is the final product.
